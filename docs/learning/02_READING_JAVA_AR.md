## 2.1 اقرأ الملف على أربع مراحل

ابدأ بالاسم والمكان، ثم عنوان الكلاس، ثم أسماء الميثودات، وبعدها افتح جسم الميثود المطلوبة. قراءة كل الأقواس من أول يوم مش أحسن طريقة للفهم.

مثال تعليمي مبسط؛ مش نسخة حرفية من ملف:

```java
package Example;

import org.testng.Assert;

public class QuantityTest {
    public void quantityIsSaved() {
        String expected = "1.25";
        String actual = "1.25";
        Assert.assertEquals(actual, expected);
    }
}
```

`package` عنوان الملف المنطقي. `import` بيعرّف الكود باسم كلاس من مكان آخر. `class` وحدة بتجمع بيانات ودوال مرتبطة. `method` دالة أو فعل محدد. جسم الدالة بين `{` و`}`. الفاصلة المنقوطة `;` نهاية تعليمة غالبًا.

## 2.2 الكلاس والنسخة منه

اعتبر الكلاس وصف وظيفة الموظف، و`new` تعيين موظف فعلي. `new SalesModulePage(driver)` يعمل كائن صفحة مبيعات مرتبط بنفس المتصفح. مش معناه إنه فتح متصفحًا جديدًا. المتصفح بيتعمل في المصنع، والصفحة تستلمه.

**Constructor** هو الميثود اللي اسمها نفس اسم الكلاس ومفيش قبلها نوع نتيجة؛ بتجهز الكائن. في صفحاتنا غالبًا تستقبل `WebDriver driver` وتجهز مكوناتها. التجهيز الطبيعي للصفحة مش المفروض ينشئ بيانات ERP بمجرد `new`.

## 2.3 المتغير والنوع والقيمة

| الكود | المعنى |
|---|---|
| `String name` | نص، زي اسم عميل |
| `int count` | عدد صحيح |
| `boolean visible` | صح أو غلط |
| `BigDecimal price` | رقم عشري مناسب للمبالغ والحساب الدقيق |
| `List<InvoiceRow>` | قائمة بنود فاتورة |
| `Map<String, Object>` | مفاتيح وقيم، زي بيانات API |
| `Set<Object>` | مجموعة تمنع تكرار نفس العنصر |
| `null` | مفيش قيمة مرتبطة حاليًا؛ غير النص الفارغ |
| `void` | الدالة تعمل إجراء ولا ترجع قيمة |
| `return` | رجّع النتيجة واخرج من الدالة |

`Map` مثل ورقة بها خانات: اسم الخانة `quantity` وقيمتها `1.25`. مرونة `Object` معناها إن القيمة ممكن تكون نصًا أو رقمًا أو قائمة؛ لذلك بنراجع نوعها قبل افتراضها.

## 2.4 public وprivate وprotected

`public`: نقطة دخول متاحة للمستدعين. الاختبار غالبًا يستخدم دوال الصفحة العامة.

`private`: تنفيذ داخلي للكلاس. لو دالة انتظار خاصة اتغيرت، الهدف إن باقي المشروع ما يحتاجش يعرف تفاصيلها.

`protected`: متاح للكلاس وتخصصاته وبعض الاستخدامات داخل الحزمة. مثال: صفحة متخصصة تعيد تعريف قراءة إجمالياتها.

الدالة بدون الكلمة دي غالبًا متاحة داخل الحزمة فقط. المكونات الداخلية `final class` غالبًا مش عامة للمشروع كله. ده بيقلل استخدام التفاصيل الداخلية بالخطأ.

`final` على متغير يمنع تغيير المرجع بعد تعيينه؛ مش بالضرورة يخلي محتويات القائمة نفسها غير قابلة للتغيير. `static` يعني عضو تابع للكلاس نفسه، مش لكل كائن. وجود `static` مش عيب وحده؛ الخطر في حالة متغيرة مشتركة بين اختبارات محتاجة عزل.

## 2.5 الوراثة والتركيب

```java
class Invoice extends SalesModulePage { ... }
```

دي وراثة: الفاتورة تخصص من صفحة مبيعات. `super(driver)` يستدعي تجهيز الأب. `@Override` معناها إن الكلاس بيقدم تنفيذًا بديلًا لدالة موجودة فوقه.

```java
private final SalesDocumentLines lines;
```

ده تركيب: الصفحة معاها مكون مسؤول عن البنود. الصفحة مش «نوع من البنود»؛ هي بتستخدم البنود. بعد التنظيم، صفحتا المبيعات والمشتريات ما بقوش يعتمدوا على بعض عن طريق الوراثة؛ القدرات المشتركة في `DocumentPage` ومكوناته.

**التفويض** يعني الصفحة تستقبل الطلب وتديه للمكون: `lines.slQuantity(...)`. مش تكرار للوظيفة؛ دي واجهة ثابتة والتنفيذ في مكان واحد.

## 2.6 الشروط والتكرار

`if` اختَر حسب شرط. `switch` اختَر من حالات محددة، زي نوع المستند. `for` كرر عددًا أو على عناصر. `while` كرر طالما الشرط قائم.

لو شفت تكرار للمحاولة، اسأل: هل له حد؟ ماذا يحدث لو كل المحاولات فشلت؟ وهل فيه دليل على سبب الفشل؟ إعادة الضغط خمس مرات مش حل لو الخيار أصلًا مش موجود في البيانات.

## 2.7 الاستثناءات

`throw` معناه إيقاف المسار الطبيعي بسبب مشكلة. `try` جرّب. `catch` تعامل مع نوع خطأ. `finally` نفّذ جزءًا سواء حصل خطأ أو لا، مثل الرجوع للنافذة الرئيسية أو محاولة التنظيف.

`catch (Exception ignored)` قد يكون مقبولًا لتنبيه اختياري، لكنه ليس مقبولًا لو هيحوّل فشل حفظ حقيقي لنجاح. لذلك مراجعة الاستثناء لازم ترتبط بمعنى العملية، مش مجرد حذف catch من كل مكان.

## 2.8 علامات TestNG وAllure

| العلامة | دورها |
|---|---|
| `@Test` | تعريف اختبار فعلي يمكن تشغيله |
| `@BeforeClass` | تجهيز قبل اختبارات الكلاس |
| `@BeforeMethod` | تجهيز قبل كل حالة |
| `@AfterMethod` | تجميع أو تنظيف بعد الحالة |
| `@AfterClass` | تنظيف أو إغلاق بعد مجموعة الكلاس |
| `alwaysRun = true` | محاولة تشغيل التجهيز/التنظيف حتى مع فشل سابق وفق قواعد TestNG |
| `@DataProvider` | مصدر عدة مجموعات بيانات لنفس الاختبار |
| `@Step` | اسم خطوة تظهر في Allure؛ لا تجعل الدالة اختبارًا لوحدها |
| `@Story` و`@Description` | وصف غرض الحالة وقصتها |
| `@Listeners` | ربط مراقبين بالتنفيذ والنتائج |

الدالة الموروثة وعليها `@Test` ممكن تتنفذ في كلاس ابن حتى لو ما كتبتش جسمها مرة ثانية. لذلك عدّ نصوص `@Test` وحده مش كفاية لحساب مجموعة التشغيل.

## 2.9 lambda وstream من غير خوف

`d -> ...` دالة صغيرة بنمررها لانتظار أو عملية. مثال: استنى لحد ما شرط على المتصفح `d` يبقى صحيحًا. `stream().filter(...).map(...).toList()` معناها خذ مجموعة، صفّيها، حوّل عناصرها، وارجع قائمة.

لو ده جديد عليك، اقرأ الجملة بمعناها: «خذ الصفوف الظاهرة، واقرأ نص كل صف، ورجّع النصوص». مش لازم تحفظ شكل السلسلة قبل ما تفهم المطلوب.

## 2.10 إزاي تقرأ ميثود حقيقية؟

افتح `Invoice/SalesFormActions.java` ثم `fractionalQuantityPersists` تحت `src/test/java`. هتلاقي تجهيز `prepare`، إضافة صنف، تغيير كمية، انتظار صافي، حفظ، مقارنة الكمية المحفوظة، ومراجعة المخزون. اكتب بجوار كل سطر: تجهيز / إجراء / انتظار / تحقق. التدريب ده هيعلمك قراءة الاختبارات أسرع من حفظ أسماء الأدوات.

# أول تنفيذ لملفات إعداد الفروع — 27 أكتوبر 2026

## السلوك الحالي محفوظ افتراضيًا

إذا لم تمرر `branch.profile`، لا تُقرأ ملفات config/branch-profiles ولا تُنفذ قراءات السياسات الإضافية. اختيار الـprofile لا يبدّل الفرع ولا يعدّل الإعداد أو ينسخ معاملات. واجهات الحساب القديمة وDiscountType وTaxMode لم تتغير.

## إعداد profile تجريبي

1. خصص فرع اختبار معتمدًا بإعدادات معلومة. هذه الدفعة لا تنشئه ولا تغيّر إعداداته.
2. انسخ `config/branch-profiles/reference.example.properties` إلى `config/branch-profiles/public-reference.properties`.
3. املأ origin ومعرف الفرع والقيم الأساسية الست من baseline تم التحقق منه، وليس من إجماليات الفاتورة. origin هو بروتوكول+مضيف+منفذ فقط، بلا مسار أو بيانات دخول. لا تحفظ كلمات مرور هنا.
4. شغّل Maven مباشرة:

```powershell
mvn '-Dbranch.profile=public-reference' '-Dsurefire.suiteXmlFiles=src/test/resources/smoke-testng.xml' test
```

للتشغيل القديم، احذف `-Dbranch.profile` من الأمر. IntelliJ يمكنه تمرير نفس الخاصية في VM options. الـlauncher يمرر الاسم إلى PowerShell، والتشغيل الأصلي داخل IntelliJ يثبت البصمة قبل التخطيط.

للتشغيل متعدد المراحل مع تحقق محلي أولًا:

```powershell
./scripts/Test-Project.ps1 -Mode Smoke -BranchProfile public-reference
```

يحفظ التشغيل `branch-profile.json` داخل مجلد أدلته، ويمرر الاسم والبصمة إلى كل مرحلة وJVM. تغيير الملف بين المراحل يوقف المرحلة التالية، ولا يعدّل المتوقع ليتوافق مع الإعداد الجديد. الاختبارات المحلية قبل التشغيل الحي تعمل دون profile. السكربت المباشر `Invoke-QualificationLevel.ps1` يقبل `-BranchProfile` و`-BranchProfileFingerprint` أيضًا. سكربت الاستكمال القديم يقرأ manifest المحفوظ ويتحقق منه قبل بدء الاختبارات.

تشغيل Maven المباشر يحتفظ بإعداد ثابت لكل كلاس. لتثبيت التوقع عبر كلاسات/JVM متعددة استخدم السكربت، أو مرر أيضًا `-Dbranch.profile.fingerprint=<البصمة المحفوظة>`؛ لا تعتمد على الاسم وحده إذا كان الملف عرضة للتعديل أثناء الرن.

## ما الذي يُفحص؟

- origin وbranchId.
- النشاط: Public / Restaurant / Construction / Concrete / CarShowroom.
- مستوى الخصم: Transaction / Items. هذه أكواد مخزنة، ولا نعيد تفسير الوصف المتضارب هنا.
- الضريبة: NetBased / ItemBased / PriceIncluded.
- الجرد: Periodic / Continuous.

لا توجد قيمة افتراضية للسياسة المجهولة. الاسم غير الآمن أو الملف المفقود أو ناقص المفاتيح أو المفتاح الزائد يفشل قبل إنشاء المتصفح. الاختلاف الفعلي بعد تسجيل الدخول يفشل التجهيز قبل @BeforeClass الخاص بالـfixtures. توجد مطابقة أخرى قبل الحالة وبعدها. المرفق Branch profile preflight يعرض expected وactual للمراجعة حتى عند الاختلاف.

## الحدود

هذه قاعدة حماية أولى وليست اكتمال مصفوفة الأنشطة. لم تتغير حسابات الضريبة أو المرتجعات أو الجرد. معدلات الضريبة والتقريب والضريبة الإضافية لم تدخل بعد في تعريف profile؛ لا يعتبر هذا الملف اعتمادًا للحسابات المالية. التحقق عند الحدود ليس قفلًا موزعًا ولا يمنع تعديل الإعداد في منتصف أمر API؛ التحقق يقرأ إعداد الجلسة في المتصفح ولا يمثل ضمانًا ذريًا من الخادم. حجز الفرع بين أجهزة مختلفة ما زال مطلوبًا. لم تُحل دلالة Transaction/Items عمليًا ولم ننشئ 60 profile.

## الاختبارات

اختبارات محلية للتعطيل والتطابق واختلاف كل محور والقيم المجهولة والملفات الناقصة وأسماء الملفات غير الآمنة، وقراءة بلا dispatch/commit مع انتظار hydration، وفشل اختيار غير صالح قبل إنشاء المتصفح. تجربة قراءة حية مستقلة تتحقق من قراءة الفرع ورفض معرف مختلف دون تغيير الفرع أو حفظ نموذج؛ ليست تشغيل Smoke كاملًا على كل سياسة.

النتيجة النهائية لهذه الدفعة: 596 اختبارًا محليًا ناجحًا، صفر فشل أو أخطاء أو تخطي؛ Spotless وفحوص الصيانة والأسرار ناجحة. السجل `target/branch-profile-full-ci.log`. تجربة القراءة الحية نجحت وأثبتت رفض branchId مختلف؛ السجل `target/branch-profile-readonly-live.log`. لم يتم تشغيل Smoke كاملة في هذه الدفعة؛ شمل التحقق الحي الدخول وقراءة الإعداد فقط دون كتابة بيانات عمل.

## حماية بيانات التجهيز والاسترجاع

واجهات التجهيز الثماني للمبيعات والمشتريات والمخازن والأصناف والعملاء والحركات المالية والمبيعات الخاصة والبيانات الأساسية تتحقق من الـprofile قبل طلب API. الـprofile ثابت في نطاق كلاس الاختبار، ويظل متاحًا أثناء التنظيف ثم يُزال من thread العامل. عند عدم اختياره لا تضيف الحماية قراءة للمتصفح.

تضيف سجلات التجهيز `_branchProfile` إلى كل سجل مُنشأ في تشغيل profile، دون تغيير البيانات الأصلية في الذاكرة. القراءة أو استبدال سجل تابع لبصمة أخرى يفشل مع الحفاظ على الملف. لا يُحوّل سجل قديم غير موصوف إلى profile تلقائيًا؛ استرجعه بالطريقة القديمة وفي فرعه الأصلي. السجلات القديمة تظل قابلة للاستخدام دون profile، والسجل الفارغ لا يملك موارد معلّقة. استرجاع سجل profile يحتاج نفس الاسم والبصمة والإعدادات.

هذه الحماية لا تغيّر اختيار السيناريوهات حسب النشاط ولا حسابات الخصم والضريبة والجرد. يلزم إثبات قواعد العمل على فرع اختبار معتمد قبل إضافة التوقعات المالية الجديدة.

نتيجة ربط التشغيل والاسترجاع: 611 اختبارًا محليًا ناجحًا، بلا فشل أو أخطاء أو تخطي، في `target/profile-runtime-full-ci.log`. اختبار توصيل السكربت المحلي أثبت وصول الاسم والبصمة إلى مخطط التشغيل ومرحلتي Maven باستخدام بدائل للعمليات الحية. لم تنفذ هذه المرحلة Smoke حية أو تغيّر إعدادات فرع.

## تطبيق الإعداد قبل الرن — مسار اختياري

```powershell
./scripts/Test-Project.ps1 -Mode Smoke -BranchProfile public-reference -ApplyBranchProfile
```

الخيار الجديد صريح ولا يغير المسار القديم. يتطلب profile معتمدًا لنفس origin ومعرف الفرع الحالي؛ لا يختار فرعًا آخر تلقائيًا. تحفظ أدلة before/target والبصمة قبل التعديل، ثم تستخدم اختيارات الشاشة، وتقارن كل حقول النموذج غير الأربعة المستهدفة قبل الحفظ. بعد الحفظ تعاد الجلسة وتقرأ بيانات الفرع المحفوظة؛ أي اختلاف أو رفض يمنع بدء الاختبارات. لا توجد إعادة إعدادات تلقائية بعد الرن ولا تجاوز لقفل التطبيق.

**قيد التحقق الحي:** رُصدت حقول السياسات معطلة في لقطة من الفرع الحالي، لكن إعادة التجربة سمحت بتغيير الضريبة داخل مسودة ثم توقفت عند اختيار الخصم. لا يكفي ذلك للجزم بمنع تعديل الفرع نهائيًا؛ توقيت تحميل النموذج وتفاعل القوائم يحتاجان إكمال تحقق. لم يُضغط حفظ، ولا نعلن نجاح تغيير السياسات وحفظها حيًا. الأداة ترفض الحقل المعطل عند محاولة استخدامه، ولا تتجاوزه. مسار ApplyBranchProfile موجود لكنه قيد التحقق وغير معتمد للتشغيل الفعلي بعد. لا تعدّل الأداة الضريبة الإضافية أو معدلات الضريبة أو إعدادات المطعم.

فحص الحماية المحلي يغطي هوية الفرع، تغيير إعداد جانبي، التوقع السابق، رفض الحفظ، وثبات نسخة البيانات المتداخلة؛ لا يحل محل تحقق الحفظ الحقيقي أو قفل موزع على أجهزة متعددة.

التحقق المحلي الأحدث: 630 اختبارًا ناجحًا بلا فشل أو أخطاء أو تخطي، BUILD SUCCESS وSpotless ناجحان في target/branch-settings-full-ci.log.

## قيد السياسات بعد الحركات — تأكيد المستخدم

أكد المستخدم أن الخصم وسياسة الضريبة والجرد تُعطل بعد وجود حركات على الفرع. يُفحص توفر كل الحقول المطلوب تغييرها قبل أي تعديل في المسودة؛ حقل واحد معطل يمنع التجهيز والرن. لا تستخدم الأداة إزالة disabled أو API للالتفاف على القيد. هذا مسار تجهيز محافظ؛ لا يعتبر دليلًا أن backend يرفض الطلب نفسه.

للتشغيل عبر سياسات مختلفة نحتاج فرع اختبار قابلًا للتجهيز قبل إنشاء أول حركة، أو فروعًا مجهزة مسبقًا لكل إعداد. مجرد حذف بيانات fixture بعد الرن لا يثبت أن الفرع عاد قابلًا لتغيير السياسات، فلا يعاد تدويره تلقائيًا. اختيار فرع آخر وتخصيص مستخدمه وقيود الترخيص ما زالت خطوات بيئة تحتاج تنفيذًا والتحقق قبل إعلان التشغيل المتعدد مكتملًا.

## اختيار فرع الـprofile لكل جلسة

اختيار الفرع أصبح متاحًا صراحة عبر `-Dbranch.profile.select=true` مع `-Dbranch.profile=demo-public-reference`، أو `-SelectBranchProfile` في Test-Project.ps1. بدون الخيار لا تتغير جلسة الفرع والمسار القديم باقٍ كما هو. الأداة تقرأ اسم الفرع من معرفه، تختاره من قائمة الحساب، ثم تحدث الصفحة وتطابق الهوية والسياسات كاملة. origin مختلف أو اسم قائمة مكرر أو فرع غير متاح يمنع التشغيل، ولا يعدّل ملف profile إلى القيم الفعلية.

```powershell
./scripts/Test-Project.ps1 -Mode Smoke -BranchProfile demo-public-reference -SelectBranchProfile
```

هذا المثال ليس إعلان اعتماد Smoke بالكامل على الفرع الجديد. الفرع يحتاج تجهيز موارده، ومستخدم الحساب يحتاج صلاحية ظهوره بالقائمة. لا تستخدم اختيار الفرع لتجاوز فشل السياسات؛ التحقق يظل كاملًا. ApplyBranchProfile ما زال يتحقق من فرع الجلسة الأصلية قبل التعديل، ولا يغيّر فرعًا آخر تلقائيًا.

اختبار BranchSessionSelectionLiveTest تحقق حيًا من الدخول للفرع demo-public-reference وإعادة تحميله دون تغيير إعداداته. السجل target/branch-selection-live.log، نتيجة واحدة ناجحة.

اختبار توصيل محلي بعمليات بديلة أثبت وصول branch.profile.select=true مع الاسم والبصمة لمخطط التشغيل ومرحلتي Maven. خيار الاستكمال محفوظ داخل plan.branchProfile.selectBranch؛ خطط الرن القديمة التي لا تحمل الخيار تظل لا تختار فرعًا. 632 اختبارًا محليًا نجحت قبل تعديل حفظ هذا الخيار، ثم أعيدت اختبارات قراءة/اختيار الفرع وتخطيط المراحل على التعديل النهائي.

التحقق الحالي لا يعتمد توازي حساب واحد عبر فروع مختلفة؛ اختيار الفرع قد يكون له أثر على جلسات المستخدم الأخرى حسب سلوك الخادم. البداية متسلسلة على الفرع المخصص. التوازي بين الفروع يحتاج مستخدمين معزولين وإثبات استقلال، ولا يستنتج من نجاح اختيار فرع واحد.

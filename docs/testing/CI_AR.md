# فحوص CI وتقارير Allure

ملف `.github/workflows/local-checks.yml` يشغّل الفحوص المحلية عند Push وPull Request، ويمكن تشغيله يدويًا من GitHub Actions بعد رفع التغييرات. يعمل على Windows وUbuntu باستخدام Temurin JDK 21. تُثبّت إجراءات GitHub ببصمات commit، وصلاحية المستودع للقراءة فقط، ولكل مهمة مهلة عشرين دقيقة.

لا يحتاج هذا الفحص بيانات دخول أو Chrome أو بيئة ERP. قائمة `src/test/resources/ci-testng.xml` تختار اختبارات الحسابات والإعدادات وتعريفات التشغيل وتوافق Java وAspectJ وملكية المتصفح وتنظيف البيانات واسترجاعها باستخدام واجهات محاكاة محلية. `CiSuiteContractTest` يمنع ضم الكلاسات الحية التي ترث `BaseTest` واختبارات الدخول المستقلة إلى هذه القائمة، ويتحقق من بقاء عقود التنظيف المحلية.

## التشغيل محليًا

```powershell
mvn --batch-mode --no-transfer-progress -Pci verify
```

هذا الأمر يبني المشروع ويختبره دون تسجيل دخول أو تعديل بيانات ERP. تظل اختبارات الواجهة الحية تشغيلًا منفصلاً بمداخلها وبيانات دخولها المعتادة. لا يلزم استخدام `mvn clean` لتشغيل الفحص؛ قد تحتوي مجلدات target القديمة على سجلات استرجاع تخص تشغيلات حية سابقة.

## النتائج

| المسار | المحتوى |
| --- | --- |
| `target/ci/surefire-reports` | ملخص الاختبارات وXML وتفاصيل الفشل |
| `target/ci/allure-results` | نتائج Allure الخام، وخطوات الاختبار والمرفقات والبيانات الوصفية |
| `target/ci/allure-report` | تقرير HTML عند توليده يدويًا |

ترفع المهمة محتويات `target/ci` كملف مرفق حتى عند فشل الاختبارات، مع اسم يحدد نظام التشغيل ومحاولة التنفيذ، ومدة احتفاظ سبعة أيام. يبقى فشل الاختبار فشلًا للمهمة؛ رفع الملفات لا يخفيه. لا يوجد نشر تلقائي للتقرير على موقع عام.

لإنشاء HTML من النتائج بعد تنزيلها إلى المسار نفسه أو بعد تشغيل الفحص محليًا:

```powershell
mvn -Pci allure:report
```

هذا يولد `target/ci/allure-report/index.html` دون فتح خادم تقرير تلقائيًا. تم التحقق من هذا الأمر محليًا.

## الفصل بين التشغيل المحلي وCI

`allure.report.generate=false` يعطل توليد HTML التلقائي وتنزيل CLI لهذا الغرض، مع استمرار كتابة النتائج الخام. `allure.report.open=false` يمنع فتح التقرير تلقائيًا عند توليد HTML. يمكن تمرير الخيارين باستخدام `-D`.

ملف Maven ذي المعرّف `ci` يضبط الخيارين على false. وعند عدم توفيرهما تكون القيمة الافتراضية false إذا كانت بيئة العملية `CI=true`، وtrue في التشغيل المحلي المعتاد. لا يفتح التقرير عندما يكون التوليد معطلًا، حتى لو كان خيار الفتح true. هذه الخيارات تتحكم في التقارير التلقائية الخاصة بالمستمع؛ أمر `allure:report` توليد يدوي مستقل.

التشغيل المحلي المعتاد يظل يستخدم `allure-results` و`allure-report` في الجذر. الاختبار باستخدام ملف Maven `ci` يكتب في `target/ci`، ولا ينظف التقارير المحلية القديمة. وعلى GitHub توجد نسخة عمل منفصلة لكل مهمة. عند تشغيل عمليات متزامنة داخل نسخة عمل واحدة، استخدم مساري نتائج وتقرير مختلفين لكل عملية عبر `-Dallure.results.directory=...` و`-Dallure.report.directory=...`؛ يجب أن يكونا مجلدين منفصلين داخل المشروع، وليس أحدهما داخل الآخر. ترفض أداة التقرير مسارات المشروع الرئيسية ومجلدات الكود والإعدادات، وتتحقق من مسار التنظيف الفعلي قبل الحذف.

# السماح باختلاف المبالغ العشرية

الإعداد موجود في `src/main/resources/amount-checks.properties`:

```properties
assertion.amount.decimal.tolerance=0.3
```

السماح قيمة ثابتة بالزيادة أو النقص، وليس نسبة مئوية. في مقارنة المبلغ العشري، نقرب الفعلي والمتوقع إلى رقمين عشريين أولًا، ثم نقارن. لو المتوقع 40.2، فإن أي مبلغ من 39.90 إلى 40.50 بعد التقريب مقبول، والحدان مقبولان. لذلك 39.8999 مقبولة لأنها تصبح 39.90، و40.5001 مقبولة لأنها تصبح 40.50. أما 39.8949 تصبح 39.89، و40.505 تصبح 40.51، فتُرفضان.

لو المتوقع مبلغ صحيح مثل 40 أو 40.00، تظل المقارنة دقيقة: 40 مقبول، لكن 39.99 و40.01 مرفوضان. المتوقع صفر يظل صفرًا. عند توقع مبلغ عشري سالب تطبق نفس المسافة بالزيادة أو النقص.

السماح للمبالغ المالية: الصافي والضريبة والإضافية والخصم والسعر والمدفوع والرصيد المالي، بما فيها المقارنات المشتركة للطباعة والتصدير. كميات الأصناف، حتى الكميات العشرية، وأرقام السجلات والأسماء والحالات تظل دقيقة. فحوص الحسابات المحلية المستقلة لا تُغيّر معادلاتها أو نتائجها الرياضية بسبب هذا الإعداد.

ضع القيمة 0 لإلغاء السماح والرجوع إلى المطابقة الدقيقة للمبالغ. يمكن أيضًا تمرير `-Dassertion.amount.decimal.tolerance=0` إلى تشغيل Java أو Maven. القيمة السالبة مرفوضة.

الفرق داخل السماح لا يعتبر فشلًا. القيم الفعلية والمتوقعة تظل ظاهرة في خطوات المقارنة. هذا استثناء مقبول للاختبارات بطلب المستخدم، وليس إصلاحًا لحسابات ERP أو تغييرًا لنتائج تشغيل محفوظ سابقًا.

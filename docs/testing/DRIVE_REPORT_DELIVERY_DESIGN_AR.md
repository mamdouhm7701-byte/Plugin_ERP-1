# إرسال تقارير التشغيل الكبيرة عبر Google Drive

## المطلوب

إرسال ملخص HTML الحالي إلى Gmail حتى عندما يتجاوز تقرير Allure حد المرفقات، مع إتاحة التقرير الكامل بصوره ومرفقاته لمستلمي الرسالة. يظل فتح Allure المحلي يعمل كالمعتاد، ولا تتغير نتائج الاختبارات بسبب فشل التسليم.

## التصميم المقترح

- تبقى التقارير الصغيرة مرفقات كما هي عند إجمالي لا يتجاوز 17 MiB.
- عند تجاوز الحد، يرفع المشروع ZIP كاملًا للتقرير الكبير إلى Google Drive، ويرسل رابط التحميل داخل النسختين HTML والنصية للميل. يرفق TestNG إذا كان ضمن الحد؛ وإذا كان كبيرًا يرفع هو أيضًا.
- الرابط لتنزيل ZIP وفكّه وفتح index.html؛ Google Drive ليس استضافة لتطبيق Allure.
- رفع عبر Google Drive API من عملية Java نفسها باستخدام OAuth بصلاحية drive.file، دون الاعتماد على وجود محادثة أو إضافة Codex قيد التشغيل.
- إعداد تفويض أولي بواسطة OAuth Desktop client من مشروع Google Cloud مفعّل عليه Drive API. يسجل المستخدم دخوله في Google داخل المتصفح. تحفظ بيانات العميل وrefresh token محليًا في ملفات يتجاهلها Git؛ لا تُطلب كلمات مرور Google أو الرموز في المحادثة، ولا تظهر في السجلات.
- المشاركة محددة بعناوين المستلمين الحالية في إعداد to وبصلاحية القراءة، دون تفعيل anyone/public. الحساب الذي يفوض Drive يملك الملفات. الحساب المقترح هو حساب الإرسال الحالي؛ لا يُفترض أنه مرتبط بالفعل.
- استخدام رفع resumable وقراءة الملف من القرص، مع مهل وإعادة محاولة محدودة للأخطاء المؤقتة. لا تُعاد محاولة إرسال SMTP بعد نتيجة قبول غير مؤكدة حتى لا تتكرر الرسائل.
- حفظ سجل محلي لمعرف ملف Drive ورابطه وحالة المشاركة والإرسال، مرتبط بمعرف التشغيل واسم المرفق وبصمته، لاستئناف تسليم نفس التقرير دون رفع نسخ غير لازمة.
- عند فشل رفع التقرير أو مشاركة الرابط، تُرسل رسالة الملخص مع وصف واضح لتعذر إتاحة التقرير والمرفقات الصغيرة الممكنة؛ تُحفظ النسخة الكبيرة محليًا لإعادة المحاولة. لا يوصف رابط غير متاح للمستلمين بأنه ناجح.
- لا تحذف ملفات Drive تلقائيًا؛ يوضح الدليل أنها تستهلك مساحة الحساب وتحتاج إدارة لاحقة.
- إعدادات GitHub Actions تأتي من Secrets منفصلة لتفويض Drive؛ ربط الجهاز وحده لا يفعل الرفع داخل GitHub.

## التنفيذ والتحقق

فصل عميل Drive عن ReportMail، وإضافة اختيار المرفقات/الروابط قبل تكوين الرسالة. تحديث قالب الميل لعرض روابط واضحة بدل تعليمات مرفق غير موجود. إضافة أداة إعداد OAuth وإعادة إرسال تقرير محفوظ دون إعادة تشغيل Regression.

اختبارات محلية تغطي حد الحجم، المشاركة للمستلمين فقط، الروابط في MIME، فشل الرفع، إعادة المحاولة، وعدم تسريب الرموز؛ خادم HTTP محلي لاختبار بروتوكول الرفع دون حساب حقيقي. تشغيل mvn -Pci verify ثم تجربة فعلية لرفع تقرير كبير وإرسال رابطه بعد إعداد التفويض.

## المتطلب المتبقي من المستخدم

اعتماد هذا التصميم، ثم إنشاء OAuth Desktop client في Google Cloud وتفويض حساب Drive مرة واحدة. لا يوجد تفويض Drive مستقل للمشروع حاليًا، ولا يمكن تفعيل الرفع الفعلي أو تأكيده قبل هذه الخطوة.

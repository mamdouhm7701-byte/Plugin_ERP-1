# تسجيل المتصفح عند فشل الاختبار

قبل التشغيل، غيّر `src/main/resources/video.properties`:

```properties
video.enabled=true
```

القيمة `false` تعطل التسجيل. يمكن تجاوز الملف لتشغيل واحد دون تعديله:

```powershell
mvn '-Dvideo.enabled=true' '-Dsurefire.suiteXmlFiles=src/test/resources/smoke-testng.xml' test
mvn '-Dvideo.enabled=false' '-Dsurefire.suiteXmlFiles=src/test/resources/smoke-testng.xml' test
```

التسجيل يبدأ عند بدء الحالة بعد تجهيز المتصفح وتسجيل الدخول، ويحفظ MP4 في `target/video` ويرفقه بـAllure إذا فشلت الحالة فقط. فيديو الحالة الناجحة أو المتخطاة يُحذف. أعطال تجهيز المتصفح قبل بدء الحالة تظل موثقة بلقطة الإعداد؛ لا يوجد فيديو اختبار قبل بدء الاختبار.

التسجيل للمتصفح نفسه من لقطاته أثناء أوامر Selenium؛ يعمل مع Local وLocalHeadless والتوازي دون التقاط التطبيقات الأخرى. المعدل الافتراضي حتى إطارين في الثانية، والعرض حتى 960 بكسل، مع الحفاظ على زمن اللقطات وتكرار الإطار السابق أثناء فترات الانتظار الطويلة. الحركة التي تحصل بالكامل بين أمرين لا تُلتقط باستمرار؛ هذا تسجيل تشخيصي لأحداث الأتمتة. تنفيذ Selenium يظل على خيطه الأصلي تحت ThreadGuard.

كل حالة لها اسم UUID مستقل. فشل التصوير أو الترميز يسجل تحذيرًا ويحافظ على نتيجة الاختبار. إعدادات إضافية: `video.frame.rate` من 1 إلى 5، و`video.max.width` من 320 إلى 1920، و`video.folder` داخل target. رفع الدقة أو المعدل يستهلك وقتًا ومساحة أكثر. لا يحتاج FFmpeg أو تسجيل شاشة Windows.

التحقق: الفحص المحلي الكامل 588 ناجحة، واختبارات توليد/إنهاء MP4 وحذف النجاح وتعطيل التسجيل. تجربة Chrome Headless بصفحة HTML محلية أنتجت MP4 فعليًا في `target/video-probe`؛ السجل `target/video-probe.log`. لم تُنشأ بيانات ERP ضمن التحقق من التسجيل.

# مراجعة وضوح المخرجات

مراجع الوضوح يراجع صياغة مخرجات الاختبارات والبجز قبل التسليم، بالتنسيق مع مراجع البيانات وملفات التشغيل. دوره تحرير الشرح، لا تغيير قواعد البيزنس أو تحويل الفشل إلى نجاح.

## حالة الاختبار

- عنوان يذكر الفعل المطلوب والشاشة أو الشرط الذي نختبره.
- شروط بداية يمكن تجهيزها وبيانات مثال محددة.
- خطوات مرقمة من الواجهة، دون حاجة لمعرفة أسماء دوال أو قراءة كود.
- نتيجة متوقعة قابلة للفحص: قيمة أو سجل أو رسالة أو أثر محدد على الرصيد.
- خطوات تنظيف تخص بيانات التجربة فقط.
- القاعدة غير المؤكدة تظل معلّمة بأنها تحتاج تأكيدًا؛ لا يصيغها المحرر كحقيقة.

## تقرير البج

1. عنوان يصف العرض الظاهر والشرط الذي يظهر فيه.
2. الشاشة والبيانات اللازمة لإعادة التجربة.
3. خطوات قصيرة مرتبة، مع ذكر أي اختيار مؤثر مثل المخزن أو نوع السداد.
4. المتوقع وفق القاعدة المعتمدة.
5. الفعلي الذي يثبته الدليل، دون تعميمه على كل الشاشات.
6. آخر تحقق ودليله؛ تُفصل النتائج التاريخية عن الإعادة الحالية.
7. السبب الفني، إن لم يثبت، يكتب كاحتمال منفصل ولا يحل محل وصف البج.

## فحص ما قبل التسليم

هل يستطيع شخص آخر تنفيذ الخطوات؟ هل تفسر الأرقام سبب الفشل؟ هل نُسبت كل نتيجة للشاشة والتجربة الصحيحتين؟ هل بقيت معرّفات الحالات والنتائج والمراجع وقواعد العمل دون تغيير؟

تُحذف عبارة مثل «راجع النتيجة أدناه» عندما لا تخبر القارئ ماذا يفعل. تستبدل المصطلحات الداخلية مثل DTO وfixture بخطوات يدوية واضحة. تبقى المراجع التقنية في أعمدتها أو في قسم الأدلة للمطور.

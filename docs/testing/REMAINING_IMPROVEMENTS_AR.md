# متابعة تحسين التغطية والصيانة والوقت

هذا الملف يسجل تنفيذ بقية أولويات المراجعة بعد حماية سعة البيئة.

1. ربط كل نشاط وشاشة بأدلة النتائج المتاحة وإعداداتها، مع فصل نجاح الحالة عن اكتمال الشاشة.
2. قياس التنفيذ والتجهيز والتنظيف من النتائج المسجلة، دون جمع مدد متوازية كأنها وقت فعلي.
3. تقسيم اختبارات تنظيف المبيعات والمشتريات إلى مجموعات أصغر حسب مسؤولية السيناريو، مع حفظ اختيار كل حالة مرة واحدة.
4. تشغيل الفحوص المحلية ومراجعة بقاء حالات الحماية دون فقد.
5. التأهيل الحي: لا يبدأ مع تشغيل مستخدم نشط أو عائق سعة غير محلول. النتائج المحلية ليست بديلًا عنه.

قرار: لا نعلن اكتمال شاشة من نجاح كلاس واحد، ولا نغير إعدادات التوازي لمجرد طول مدة الكلاس؛
السرعة تحتاج مقارنة نفس المجموعة على بيئة ذات سعة كافية. لا حذف بيانات أو رفع commits ضمن هذه المهمة.

## ما نُفّذ

- أداة `build_run_evidence.py` تربط نتائج محفوظة بمصفوفة النشاط والشاشة مع رابط الدليل
  والإعدادات. نجاح حالة يبقى دليلًا جزئيًا ولا يرفع قبول الشاشة إلى مكتمل.
- نفس الأداة تقيس التجهيز والتنفيذ والتنظيف وتعرض أبطأ الكلاسات، وتحسب اتحاد الفترات
  المتداخلة بدل جمعها كوقت فعلي. ستة اختبارات محلية تراجع الحساب والربط والحالات الموروثة.
- تقسيم55 حالة تنظيف مبيعات إلى9 ملفات، و48 حالة تنظيف مشتريات إلى8 ملفات؛ أكبر ملف
  بعد التقسيم270 سطرًا. أجسام الحالات نفسها مقارنة بالأصل لم تتغير، وكل مجموعة أضيفت
  إلى الحزم التي كانت تشغّل الكلاس الأصلي. اختبار مستقل يراجع الحجم واختيار الحزم.
- استخراج حماية عضوية مخزن الفرع من مالكي بيانات البيع والشراء إلى
  `TestSupport.OwnedBranchStoreMembership`؛ يبقى توثيق الملكية واستعادة الطلبات غير المحسومة
  في مالك البيانات الأصلي. الاختبارات تراجع بقاء المخازن الأخرى والافتراضي ومنع التكرار.
- إصلاح مدخل تكرار البيزنس: قائمة بداية TestNG كانت ثابتة وتمنع استبدال الخطة. اختبار
  محلي فشل بـUnsupportedOperationException قبل الإصلاح، ثم نجح بعده. المحاولة الحية
  الأولى توقفت قبل الحالات وحُذف فرعها المؤكد، ولم تُحسب جولة ناجحة.

## حدود ما لم يُثبت بعد

بقية الملفات الكبيرة ما زالت تحتاج تقسيمًا؛ هذا التغيير لا يدعي إنهاء كل الملفات فوق400 سطر.
لا نوسع قائمة التوازي ولا نعد بزمن أقل من7 ساعات دون قياس كامل على بيئة ذات سعة كافية.
التأهيل الحي المحدود اكتمل لمطاعم/خصم حركة/صافي/دوري/إضافية غير مفعلة، بمتصفح واحد:
ثلاث جولات،9 استدعاءات ناجحة في كل جولة، ونفس الاختيار والإعدادات والمتصفح والإصدار،
مع تأكيد حذف الفروع الثلاثة. التقرير `target/restaurant-stability-verified/stability-summary.html`.
هذا لا يغطي كل الأنشطة أو كل إعدادات الضريبة والإضافية.

التحقق المحلي النهائي:908 اختبارات Java دون فشل أو خطأ أو تخطٍ في
`target/remaining-priorities-release-check.log`، مع20 اختبار Python لربط الأدلة
وحساب الثبات ومراجعة تقسيم التنظيف. المراجعة المستقلة للتغييرات المحددة لم تجد
ملاحظات حرجة أو مهمة؛ لم تكن إعادة تحقق حي مستقل.

قراءة السعة قبل وبعد التأهيل كانت متساوية:47 مخزنًا مستخدمًا من50، و3 فروع مستخدمة
من50. لم تُحذف بيانات خارج ملكية التجارب. قياس أول جولة سجّل نحو95 ثانية تجهيز،
و91 ثانية تنفيذ، و250 ثانية تنظيف؛ مدد Allure فقط وليست كل وقت تجهيز وحذف الفرع.
لا تبرر هذه العينة وحدها رفع التوازي أو الادعاء بتحقيق زمن الحزمة الكاملة المستهدف.

# إثبات قابلية تكرار التشغيل

هذا الملف يشرح تكرار نفس الاختيار ومقارنة أدلته. لا يكفي نجاح رن واحد، أو إعادة محاولة
ناجحة بعد فشل، للقول إن الاختبار ثابت.

## الفحوص المحلية

من PowerShell في المشروع:

```powershell
./scripts/Test-Stability.ps1 -Mode Local -Repeats 3
```

يشغل حزمة CI كاملة ثلاث مرات، بمخرجات مستقلة، ثم يقارن نفس الحالات ونفس بصمة ملفات
الكود والإعدادات. هذا يقيس إطار الاختبار محليًا؛ لا يثبت ثبات شاشات ERP الحية.

## البيزنس الحي

```powershell
./scripts/Test-Stability.ps1 -Mode Business -Repeats 3
```

تفتح نافذة الاختيار مرة واحدة. اختر التننت والبيئة والنشاط والخصم والضريبة والجرد
والإضافية والمجموعة وعدد المتصفحات. كل جولة تعمل في تشغيل مستقل وبفرع جديد بنفس
الإعدادات؛ لا تنشئ فرعًا لكل حالة. يستخدم التجهيز والتنظيف المعتادين وقفل الرن الحي.
لا توقف تشغيلًا آخر ولا تتجاوز قفله. تعذر تجهيز أو تأكيد تنظيف جولة يوقف الجولات التالية.
بيانات الدخول تمر في ذاكرة التشغيل إلى الجولة ولا توضع في وسيطات الأمر أو ملف الطلب.

لو عدد المتصفحات الفعلي تغير لحماية الذاكرة، التقرير يقول إن المقارنة غير متكافئة.
يقارن أيضًا اسم المتصفح وإصداره الفعليين من التقرير في الجولات الحية؛ غياب هذه البيانات
يمنع إثبات التكافؤ، واختلافها يجعل المقارنة غير متكافئة.
لا يتم تثبيت عدد متصفحات أكبر من قدرة الجهاز لتجميل نتيجة القياس.

## قراءة النتيجة

الأدلة تحت `target/stability/<معرف التجربة>`، والملخص `stability-summary.html`:

| النتيجة | معناها |
|---|---|
| STABLE_PASS | نفس الحالات ونفس الإعدادات نجحت في كل الجولات دون تخطٍ أو أخطاء تجهيز وتنظيف مسجلة |
| UNSTABLE | نتيجة الحالة أو سبب توقفها اختلف بين الجولات |
| REPEATED_FAILURE | فشل أو تخطٍ متكرر؛ ليس نجاحًا ولا عيب اختبار تلقائيًا |
| NOT_COMPARABLE | اختيار الحالات أو الإعدادات أو عدد المتصفحات الفعلي اختلف |
| BLOCKED | جولة أو نتيجتها ناقصة، أو التجهيز أو التنظيف غير محسوم |

TestNG قد يضم الطرق المستبعدة عمدًا من اختيار المجموعة داخل `total` و`ignored`.
الجولات الجديدة تحفظ `selection-manifest.json` قبل التنفيذ. المقارنة تراجع الطرق
المطلوبة مقابل المنفذة والاستبعاد الصريح؛ لا تعتبر طريقة مطلوبة غائبة نجاحًا، ولا
تتجاهل `ignored` بلا خطة موثقة. الحالات المتخطاة داخل الاختيار تظل مانعة للنجاح الثابت.

كل حالة تعرض نتائجها وأسباب التوقف عبر الجولات. احتفظ بالخطأ الأصلي والمرفقات
وملخص تصنيف النتيجة داخل مجلد الجولة لتحديد هل السبب تطبيق أو اختبار أو بيئة.
الفشل المعروف لا يعطّل التست ولا يتحول إلى نجاح. النجاح يشهد للمجموعة والإعدادات
المسجلة فقط، وليس لكل الأنشطة أو لكل التغطية.

## نتيجة التحقق في28 أكتوبر

نجحت حزمة الفحوص المحلية في ثلاث جولات متتالية:888 اختبارًا في كل جولة، دون فشل
أو تخطٍ أو حالات مستبعدة، وبنفس الحالات والإعدادات. النتيجة `STABLE_PASS`، والدليل
في [سجل الجولات المحلية](evidence/repeatability-local-2026-10-28.json).
أضيفت بعدها ثلاث حالات مستقلة لفحص تأكيد التنظيف قبل بدء الجولة التالية.
التأهيل الحي لم يبدأ لأن رن IntelliJ الموجود كان لا يزال ينفذ اختبارات؛ لم يتوقف أو يتم تجاوز قفله.

## تأهيل حي لاحق في نفس اليوم

اكتملت ثلاث جولات مطاعم/خصم حركة/صافي/دوري/دون إضافية، بمتصفح Chrome156.0.8078.48
واحد:9 استدعاءات ناجحة في كل جولة، دون فشل أو تخطٍ داخل الاختيار أو أخطاء تجهيز وتنظيف.
الفروع الثلاثة تأكد حذفها. النتيجة `STABLE_PASS` للمجموعة المحددة فقط.
الدليل [تكرار المطاعم الحي](evidence/restaurant-live-repeatability-2026-10-28.json)،
والتقرير `target/restaurant-stability-verified/stability-summary.html`.

خطة هذه الجولات استُرجعت بعد التنفيذ من نفس نسخة مخطط التشغيل المجمعة، ويسجل
التقرير مصدرها بصراحة؛ الجولات المستقبلية تحفظها قبل التنفيذ. طرق الطاولات الثلاث
الخارجة عن الاختيار لا تُعرض كتخطٍ لطرق مطلوبة. XML الأصلي بقي كما هو.
محاولة أولى سابقة توقفت قبل الحالات بسبب قائمة TestNG ثابتة؛ أصلحها اختبار محلي
أظهر الفشل ثم النجاح، وحُذف فرعها. تلك المحاولة محفوظة كـBLOCKED ولا تدخل النجاح الثلاثي.

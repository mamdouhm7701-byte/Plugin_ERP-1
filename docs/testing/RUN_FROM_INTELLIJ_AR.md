# التشغيل من IntelliJ واختيار العدد كل مرة

من قائمة التشغيل بجوار زر Run اختر **ERP - Run tests** ثم اضغط Run.

تظهر نافذة مستقلة باسم **ERP Test Runner** فيها:

1. مستوى الاختبار: Smoke أو Sanity أو E2E أو Regression أو Qualification (المستويات الثلاثة بالترتيب).
2. الحد الأقصى لعدد المتصفحات: من 1 إلى 6، والافتراضي 3.
3. Browser display: اختر **Headless** لإخفاء المتصفحات أو **Visible browsers** لرؤيتها أثناء التنفيذ. يمكنك تغيير الاختيار كل رن؛ الافتراضي Headless.
4. Start tests لبدء التشغيل، أو Cancel للإغلاق دون بدء أي اختبارات.

لا يحتاج تغيير العدد إلى تعديل XML أو كتابة أوامر Terminal. إعداد **ERP - Run tests** أصبح من نوع **TestNG**؛ بعد الاختيار تظهر شجرة الحالات داخل Run في IntelliJ: اسم الحالة، الجاري تنفيذها، الناجح، الفاشل، المتخطّى والمدة. الضغط على الحالة يعرض تفاصيل الخطأ والسجل. الاختبارات تعمل Headless.

العدد المختار حد أقصى. إذا كانت ذاكرة الجهاز قليلة، قد يختار المدخل عددًا أقل ويعرض المطلوب والفعلي والذاكرة المتاحة في Console. يستخدم المدخل نفس `ParallelSuitePlanner` ونفس قائمة الكلاسات المسموح بتوازيها: مرحلة مستقلة بالتوازي، ثم الاستثناءات بالتتابع. اختيار 6 لا يجعل كل الحالات متوازية. تبقى ملفات الخطة و`plan.json` في `target/validation/native-<id>/`، ونتائج Allure في مسارها المعتاد المحدد بإعدادات المشروع.

إعداد التشغيل المشترك محفوظ في `.run/ERP - Run tests.run.xml`، ومدخله `src/test/resources/interactive-testng.xml`. إن لم يظهر الإعداد فورًا بعد سحب الملفات، أعد تحميل المشروع. يمكن أيضًا تشغيل هذا XML من IntelliJ. زر Make يبني التعديلات قبل التشغيل؛ لا ينفذ المدخل فحوص CI المحلية قبل كل رن حي كما كان يفعل مدخل PowerShell.

الإلغاء قبل Start tests لا يتصل ببرنامج ERP ولا يغيّر بياناته. لا يبدأ التشغيل الحي بمجرد فتح الملف. يمنع القفل المشترك بدء رنين منفصلين من هذا المدخل أو سكربت PowerShell على نفس المشروع. الرن الحالية التي بدأت بالمدخل القديم لا تتحول إلى شجرة TestNG؛ المتابعة الجديدة تبدأ من الرن التالية. لم يتغير نجاح أو فشل أي حالة ERP.

## التحقق

مرت 8 فحوص محلية للمدخل دون جلسة ERP: مطابقة اختيار كل حالات Smoke وSanity وE2E وRegression مرة واحدة، حدود الذاكرة والمعالج، ترتيب Qualification، منع تداخل رنين، واختبار TestNG محلي يثبت وصول أحداث بدء ونجاح الحالات بعد استبدال الـXML الفارغ بالخطة. جرى البناء في مجلد تحقق منفصل لحماية الرن الحية الجارية؛ لم تُعد اختبارات ERP كاملة لهذا التغيير.

ظهور 3 Passed فورًا عند تشغيل InteractiveTestLauncherTest يعني تشغيل اختبارات محلية للأداة، وليس تشغيل الواجهة أو اختبارات ERP. اختَر إعداد ERP - Run tests من القائمة العلوية بدل الرن الخاص بكلاس الاختبارات.

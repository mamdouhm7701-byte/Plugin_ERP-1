# حماية بيانات الاعتماد — 23 أكتوبر 2026

## ما ثبت

كان ملف `src/test/resources/Test-Data/Login.data.json` يحتوي كلمة مرور فعلية رغم إفراغ ملف Login.properties. الفروع القديمة تضمنت بيانات دخول في الملفين. لذلك نجاح الدخول أو إفراغ ملف واحد لا يغلق تسريب الأسرار.

## الحماية الحالية

- أُفرغ ملف بيانات الدخول JSON؛ لا توجد مراجع له في الاختبارات الحالية.
- أزيلت ملفات outputs المولدة من فهرس Git فقط؛ النسخ المحلية بقيت على القرص.
- يتجاهل Git ملفات الإعدادات المحلية وملفات البيئة والمفاتيح الخاصة والتقارير المولدة.
- `python scripts/check_secrets.py` يفحص الملفات المتتبعة ويعرض المسارات وأسماء المفاتيح فقط. لا يطبع القيم.
- `python scripts/check_secrets.py --staged` يفحص محتوى الفهرس، حتى لو كانت نسخة العمل مختلفة. فُعّل محليًا عبر `.githooks/pre-commit` و`core.hooksPath=.githooks`. على أي نسخة جديدة يجب تفعيل المسار نفسه؛ الخطاف ليس إعدادًا ينتقل تلقائيًا بالنسخ.
- أضيفت خطوة فحص إلى workflow الحالي؛ لم تُرفع أو تتحقق على GitHub بعد.
- نجحت اختبارات سياسة الفحص الأربعة والفحص الحالي وفحص الفهرس. هذا فحص محدود لقيم إعدادات الاعتماد وأنواع الملفات، وليس ضمانًا لاكتشاف كل سر أو بديلًا لأداة متخصصة لفحص الأسرار.

## تنظيف التاريخ المُجهّز ولم يُرفع

توجد نسخة معزولة داخل `target/security-preview.git`، مع تقرير آمن في `target/security-preview-manifest.json`. نُظف التاريخ من ملفي الدخول ومجلدات التقارير والسجلات والمخرجات، ثم أُعيدت قوالب فارغة وحماية الملفات للفروع main وTestCodeex وEdit وTrans-Between-Stors. اجتازت رؤوس الفروع الأربعة سياسة الفحص المحلية.

لم يُعدّل تاريخ نسخة العمل الأصلية أو فروع GitHub. رفع التاريخ المنظف يحتاج تحديثًا إجباريًا للفروع الأربعة بعد التأكد من أن رؤوسها لم تتغير؛ يجب عدم استخدام push --mirror كي لا تُرفع مراجع Codex المحلية. أي تغييرات متزامنة في فرع GitHub تستلزم إعادة تجهيز التنظيف قبل الرفع. نسخة التجربة لا تضم التعديلات غير الملتزمة في مساحة العمل.

إعادة كتابة التاريخ تغير معرّفات commits وتتطلب تنسيق النسخ المحلية الأخرى. كما أن إزالة الفروع لا تزيل بالضرورة مراجع pull requests أو التخزين المؤقت لدى GitHub أو النسخ المستنسخة. راجع [تعليمات GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).

## ما لم يكتمل

- رفع تغييرات الحماية والتاريخ المنظف إلى GitHub.
- التحقق من نسخ نظيفة جديدة ومن CI بعد الرفع، ومراجعة مراجع PR والتقارير المنشورة عند الحاجة.
- تدوير كلمات المرور المكشوفة على ERP وإبطال القديمة. حذفها من Git أو تجاهل ملفاتها لا يبطلها.

النسخة الأصلية والنسخ المعزولة المحلية قد تحتوي بيانات تاريخية حساسة؛ كلها محلية وليست مادة للنشر أو المشاركة. لا ترفع target أو السجلات الخام أو ملفات الإعدادات المحلية.

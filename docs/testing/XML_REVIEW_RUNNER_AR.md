# اختيار ملف التشغيل ومراجعة الفواتير

من قائمة التشغيل في IntelliJ اختار **ERP - XML review**، ثم اضغط Shift + Alt + F10 واختاره لو مش ظاهر عندك تلقائيًا.

1. اختار Cloud أو Test والتننت والرابط. بيانات الدخول الفارغة تستخدم الإعدادات المحلية.
2. اختار النشاط والخصم والجرد والإضافية لو محتاجها.
3. من قائمة XML اختار الملف. الوصف أسفله يوضح وظيفته، ومعه الكلاسات والفلاتر الموجودة بالفعل في الملف.
4. اختار عرض المتصفح واضغط تجهيز الفرع وبدء التشغيل.

التشغيل القديم **ERP - Business run** مستمر بنفس الاختيارات. الشاشة الجديدة تستخدم نفس تجهيز الفرع بالـAPI والتحقق منه وتنظيف البيانات المملوكة. ملفات الواجهة الداخلية وملفات CI والإصدارات القديمة ليست في القائمة. أي ملف مستقل جديد ينتهي بـtestng.xml يظهر تلقائيًا؛ الأفضل إضافة وصف عربي محدد له في XmlSuiteCatalog.

## ملف مراجعة الفواتير

اختار نشاط **المطاعم** وملف **invoice-tax-review-testng.xml**. النشاط ده مطلوب لإتاحة فاتورة المطعم مع المبيعات ونقاط البيع والمشتريات.

يعمل على ثلاث سياسات تلقائيًا، بغض النظر عن سياسة الضريبة المحددة في الشاشة:

- الضريبة على الصافي.
- الضريبة على الأصناف، ومعها حالة صنف معفى.
- السعر شامل الضريبة.

كل السياسات تظهر في شجرة TestNG داخل نفس تشغيل IntelliJ، ولكل سياسة فرع جديد بالـAPI. الحالات داخل نفس الجولة تشترك في الفرع، ولكل حالة أصناف وحركات تخصها. لا ينشئ فرعًا لكل تست كيس. لا يبدّل سياسة فرع عليه حركات. الخصم والجرد والإضافية يحتفظون باختيارك؛ هذه المجموعة لا تختبر كل تركيبات الخصم والجرد.

| الشاشة | المراجعة |
|---|---|
| فاتورة المبيعات | إضافة وطباعة ومقارنة الأرقام؛ التحقق من منع تعديل وحذف الفاتورة المحفوظة وفق العقد الحالي في المشروع، وثبات المخزون والمبالغ |
| نقاط البيع | إضافة وتعديل الكمية من1 إلى3 وحذف وطباعة ومراجعة الأرقام والمخزون |
| المطعم | إضافة وتعديل الكمية من1 إلى3 وحذف وطباعة ومراجعة الأرقام؛ الإضافية حسب اختيارك وبحد أدنى25 للوحدة |
| المشتريات | إضافة وتعديل الكمية من1 إلى2 وحذف وطباعة ومراجعة الأرقام والمخزون مع مورد خاضع للضريبة |

الأمثلة: الصنف100 قبل الضريبة → ضريبة15 وصافي115؛ أو115 شامل الضريبة → نفس النتيجة. الصنف المعفى تحت ضريبة الأصناف ضريبته صفر. للمطعم مع الإضافية:10 قبل الضريبة → إضافية25 وضريبة5.25 وصافي40.25؛ وعند كمية3 يصبح الصافي120.75. الأرقام متوقعة من حساب مستقل، ثم تقارن بالشاشة والفاتورة المحفوظة. الطباعة تفحص محتوى التقرير أو الإيصال الفعلي والصافي؛ لا تختبر طابعة ورقية.

حالات الإضافة والتعديل والحذف والطباعة مستقلة: فشل حالة لا يحول باقي الحالات إلى نجاح وهمي. الحذف هنا من الواجهة لما يكون متاحًا؛ تنظيف نهاية التشغيل مسار مستقل ولا يُحسب كاختبار زر الحذف.

## النتائج وحدود التشغيل

ملفات XML من الشاشة الجديدة تعمل حاليًا بمتصفح واحد، مع الحفاظ على ترتيب XML وفلاتر الطرق والبارامترات. العدد مقفول على1 ومكتوب في الشاشة؛ التشغيل القديم ما زال يدعم اختيار عدد المتصفحات.

النتائج في target/validation/xml-<معرف التشغيل>، وداخل كل سياسة:

- تفاصيل الحالات ونتائجها تظهر مباشرة في شجرة TestNG وConsole داخل IntelliJ.
- نتائج Allure ومرفقاتها تستخدم مسار التشغيل المعتاد المشترك، مع فصل السياسات بأسماء المجموعات.
- نتائج TestNG والتقرير تستخدم مسار التشغيل المعتاد؛ الحالات تظهر تحت اسم سياسة الضريبة.
- selection-manifest.json وxml-selection.json: الحالات المختارة والملف، داخل مجلد كل سياسة. إعداد الفرع وأدلة تنظيفه محفوظة في مجلد business المعتاد.
- summary.json: يؤكد تجهيز كل سياسة وتنظيفها أو سبب منع الانتقال للتالية.

summary.json في المجلد الرئيسي يسجل تجهيز وتنظيف السياسات. نجاح الاختبارات وفشلها يظهران في TestNG والتقرير. فشل تست مع تنظيف مكتمل لا يمنع تجربة السياسة التالية. فشل البيئة أو التجهيز أو عدم تأكيد التنظيف يوقف الباقي ويحافظ على سجلات الاسترجاع. يجب عدم تشغيله بالتوازي مع تشغيل ERP آخر؛ يستخدم قفل التشغيل الحالي.

تشغيل XML مباشرة خارج الشاشة يراجع سياسة الفرع الحالية فقط. التنفيذ الآلي للسياسات الثلاث موجود في ERP - XML review.

التحقق المحلي يثبت التخطيط والحسابات وتجميع الكود، ولا يثبت نجاح الحالات الجديدة على ERP. يلزم تشغيل حي بعد انتهاء أي رن قائم.
